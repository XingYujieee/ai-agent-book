# Task 1｜第 1 章笔记

详细命令和文件在[实验记录](experiment.md)。这里是我做完 1-1 到 1-4 后，回头给自己留下的解释。

## 1-1：计算器为什么会反复调用

我把同一道算术题放进五种上下文模式：完整、无历史、无先前推理、无工具定义、无工具结果。完整组和隐藏工具结果组最后都答了 4000，但完整组只叫一次工具，隐藏结果的那组叫了六次。计算器在本地算完，不代表模型看到了返回值；这正是两组过程差很多的原因。

另外几组也值得记。无历史组到第 10 轮还在重复调用，无先前推理组却在 2 轮内答对。删掉工具定义后，回答里出现过一段像工具调用的文字，实际调用数是 0。以后我查这类问题，会先看 API 事件和返回值，再读模型写出来的解释。

## 1-2：离线搜索轨迹能说明什么

离线演示里，第一次搜索只找到定义，第二次才补到用途。我终于看清了模型为什么会再搜一次。不过搜索结果是预设的；这段轨迹只适合看循环怎样接续，不能证明网络服务通了。要核实真实搜索，还得找完成的工具事件和来源链接。

## 1-3：315.29 公里从哪里来

首都距离题要先拿坐标，再算十个首都的 45 种配对。结果是吉隆坡和新加坡约 315.29 公里。我去 JSON 里找了完成的搜索和代码调用，才把这个数写下来。换一套坐标取点，距离可能略有变化，所以“最近”还要带上直线距离和数据来源。

这题的排障也够我记一阵：从 `InvalidApiKey` 到 `Bad Request`，地域、业务空间、请求字段都得逐个查，不能把报错一概归到欠费。密钥只核对是否设置，不打印原文。另一个技术分析请求没有说明数据源和指标，先问清再调用工具，这一步也能从轨迹里核对。

## 1-4：改写提示词时丢掉了什么

耳机海报要求出现指定文案，历史改写词却把文字放进负面提示。后面的图缺字，源头在改写这一步。比较宽泛的“AGI 后程序员”则给了改写发挥空间：它补出人物和场景，让构图更具体。

因此我会先对着原需求检查硬条件，再讨论画面是否更有意思。这次只是同一工具的单次小对照，不能拿来比较不同模型的能力。

第 1 章给我的实际用处，是学会翻结果文件。答案、调用轨迹和成本放在一起看，许多“看上去做对了”的差别才会露出来。
