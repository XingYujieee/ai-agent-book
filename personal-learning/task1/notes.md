# Task 1 学习笔记：AI Agent 入门

## 1. Agent 的组成与边界

`Agent = LLM + 上下文 + 工具` 是工程上的简化公式。LLM 做决策，上下文承载当前可见的信息，工具提供观察和行动接口。Agent 与文件、网页、数据库、用户等外部环境形成交互闭环；环境本身不属于 Agent。

## 2. ReAct 循环

模型读取当前上下文，决定是否调用工具；工具执行后，结果作为新消息进入上下文，模型再决定下一步。离线搜索示例展示了两轮“思考 → 行动 → 观察”：第一次结果不够完整，才触发第二次搜索。

## 3. 工具定义与工具结果不是一回事

工具定义告诉模型“能做什么”；工具结果告诉模型“刚才执行后发生了什么”。对照实验中，两组都能看到计算器工具定义，因此都能调用工具。但 `no_tool_results` 组看不到返回值，即使工具本地已经算出 4000，模型也不能据此确认答案。

## 4. 结果正确不等于过程可靠

这次消融组最终手算出 4000，但多用了 5 轮、5 次工具调用。如果任务涉及实时汇率、PDF 数据或外部系统状态，模型未必能用已有知识补出正确结果。因此评价 Agent 时要同时看最终答案、证据来源、执行轨迹和成本。

## 5. Harness 与编排

Harness 负责构造上下文、接入工具、管理循环，并加入约束、验证和纠正。固定步骤可用工作流；只有任务需要根据环境反馈动态选择路径时，才使用更自主的 Agent。复杂度应由任务与评估结果驱动。

## 6. 后续要带着的问题

- Agent 每轮实际收到了哪些消息？
- 工具是否真的执行？结果是否传回模型？
- 最终答案有何证据，是否存在重复调用或无依据推断？
- 换成更复杂任务后，当前观察能否重现？
