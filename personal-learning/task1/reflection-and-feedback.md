# Task 1 学习心

## 学习心得

学习第 1 章后，我对 Agent 的认识从“模型会调用工具”变成了“模型在每一轮依据它真正看见的内容作决定”。离线轨迹让我看清了思考、行动和观察如何接续：第一次搜索没有覆盖完整问题，才会有第二次搜索。

实际做上下文对照时，我看到两个模式都得出了 4000，但过程差别很大。完整模式只调用一次计算器；移除工具结果后，模型反复尝试计算器和代码工具，最后自己算出答案。这让我意识到，只看最终数字会错过关键问题：工具执行成功并不意味着模型收到了结果，更不意味着答案得到了工具结果的支持。

我接下来希望养成查看执行轨迹的习惯，分别记录模型看到了什么、工具做了什么，以及最终结论依据什么。对于更复杂的任务，我也会避免用一次运行就断定某种设计一定更好。

做 1-3 时，我第一次明确区分了“回答声称用 Python 计算”和“结果文件里确实有完成的代码调用”。在首都距离题中，我能顺着搜索来源、代码和日志找到 315.29 公里这个数字从哪里来。API 排障也让我明白，同一个 `Bad Request` 背后可能有地域、请求格式或密钥输入等不同原因，要用最小请求逐步缩小范围。

做 1-4 的小对照时，我看到耳机海报的原始需求要求出现指定文案，而历史改写词却排除了文字。直接生成的版本保留了文案，改写词生成的版本没有。对我来说，这比“哪张更漂亮”更重要：工作流里的每一步都应该接受检查，尤其不能悄悄丢掉用户明确提出的要求。宽泛需求里，改写又确实给画面增加了叙事；所以我会按需求类型判断它是否有帮助。

目前我的 1-1 是两组个人对照，1-2 是离线实操，1-3 完成了首都题，1-4 是同一生图工具的简化对照。仓库完整验收的历史证据能帮助我学习，但不能写成我的个人实测。我希望下一步补齐联网搜索、澄清任务和更多重复运行，让自己的结论更扎实。
