# Task 3｜第 3 章笔记

做记忆实验时，我发现“存下来”和“找回来”经常被说成一回事。BM25 的结果让我分清了它们：材料明明在库里，查询换个说法，照样找不到。

## 记忆里要留下什么（3-1、3-2）

作者保存的四种记忆模式评估中，增强笔记的总分最高；Advanced JSON Cards 在主动服务类达到 95%，跨会话拼接类只有 60%。卡片很方便，但它未必装得下时间、来源和两次说法之间的冲突。我更愿意让短卡片负责定位，原始记录留着供回查。

## 从词到语义（3-4、3-5、3-6）

本机 BM25 精确词 Recall@5 为 100%，纯同义词查询是 0%。这不是它“忘了”，是词法检索根本没见到那些词。稠密向量能处理部分语义改写；ANNOY、HNSW 是找向量近邻的索引，负责快慢和更新方式，不负责理解句子。作者历史对照里两者召回都是 1.0，ANNOY 添加数据要重建，HNSW 可以追加。

词法与向量结果还能融合。RRF 主要看名次，加权融合还要处理分数尺度。重排多花时间，作者保存的 3-6 小数据里也没提高 MRR。步骤加多之前，我会先看它究竟补了哪些错题。

## 关系、追问与片段背景（3-7 到 3-11）

RAPTOR 把材料逐层概括成树，GraphRAG 则把实体关系连起来。两种结构都怕把原文读错：一条边或者一层摘要偏了，后面的查询就跟着偏。

Agentic RAG 可以决定要不要再搜。本机 3-8 的离线题，多轮比单轮找回更多证据，但子查询预先写好了；我看到的是这条路线可能有用，没验证模型能否自己问出下一句。

“好的，就订这个吧”脱离前文几乎没法检索。给片段补背景后，作者 3-10 历史活动的 BM25 Recall@1 从 60% 到 80%，本机 3-11 八问教学集从 62.5% 到 75%。补背景也会增加索引成本，本机没有重新用 LLM 生成那些前缀。作者 3-11 的 60 题里，普通窗口、带前缀、双层记忆总体通过率分别是 78.3%、86.7%、95%；我会保留这组结果，同时检查卡片是否过期。

## 隐私与经验（3-3、3-12）

脱敏的十二条合成日志里，正则漏下 9 处，混合方法没有残留泄漏，却误删更多内容。两种错误都实际影响使用，我没法只挑一个百分数写成“最好”。

3-12 用判例因子归纳案件原型。原始 CAIL 压缩包没有随仓库提供，我本机没重跑。看这类建议时，我还是要能回到原判例和适用条件。

我会先确认材料在不在，再看检索有没有找到，最后才查回答有没有用对。三个问题分开，定位错误会容易一些。
