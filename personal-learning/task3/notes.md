# Task 3｜第 3 章笔记

我把这一章当作一个连续的问题：记忆存在哪里，怎样找回来，找回来以后还能不能信？

## 3-1 到 3-4：存下来的不一定够用

“记住”不只是复述上一轮，还可能要接起几次会话，甚至在没人提醒时主动找出相关旧事。作者保存的四模式评估里，增强笔记总分最高；Advanced JSON Cards 在主动发现一类得 95%，在跨会话拼接一类只有 60%。卡片好用，也有它没装下的东西。

长期记忆我更愿意分两层看：短卡片帮我快速定位，原始记录留下时间、出处和上下文。压短的时候，如果把冲突和先后顺序一起压没了，后来就很难纠正。

## 3-5、3-6：检索各有盲区

BM25 擅长找出现过的词。本机精确词 Recall@5 是 100%，纯同义词查询是 0%。稠密向量能补一部分语义改写；ANNOY 和 HNSW 则负责在向量里更快找邻居，不会替模型读懂原文。作者历史对照里两者召回都是 1.0，不过 ANNOY 增量更新要重建，HNSW 可以追加。

混合检索把词法和语义结果放在一起，再按需要重排。RRF 合并的是名次，加权融合还得顾及分数尺度。作者保存的 3-6 小数据里，多一道重排没有提高 MRR。我会先看错题，再决定是否值得多花这一步。

## 3-7 到 3-9：关系和追问

RAPTOR 把片段逐层概括成树，GraphRAG 把实体间的关系连起来。结构搭好了也得回原文检查：一条关系抽错，后面的推理就会沿着错路走。

Agentic RAG 让模型决定要不要继续搜。本机 3-8 离线题里，多轮检索比一次检索找回更多证据，但下一轮子问题是预写的。我看到的是“多问有可能补齐”，还没有看到模型一定能自己问对。

## 3-10、3-11：碎片要带背景

“好的，就订这个吧”单独拿去检索，几乎看不出订了什么。给片段补简短背景后，作者 3-10 历史活动的 BM25 Recall@1 从 60% 到 80%；本机 3-11 八问教学集从 62.5% 到 75%。背景有帮助，也增加索引成本。本机这次没有重新用 LLM 生成前缀。

作者 3-11 的 60 题里，普通窗口、带前缀、双层记忆的通过率依次是 78.3%、86.7%、95%。我会记下这组差别，同时继续问：卡片是否过期，原文有没有相反证据？

## 3-3、3-12：隐私与经验

本机脱敏的十二条合成日志里，正则漏下 9 处，混合策略没有残留泄漏，却误删更多信息。只追求“删干净”，也可能把排错线索删掉。

3-12 从判例里抽因子、聚原型，再给建议。我能理解这个思路，但原始 CAIL 压缩包没随仓库提供，本机没有重跑。面对判例，我仍要回到原文和适用条件，不把压缩后的建议当裁决。

我现在看检索结果，会先问证据有没有进候选集，再问它排在哪里，最后问回答有没有用对。Recall@k 好看，只过了第一关。
