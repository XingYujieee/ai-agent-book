# Task 4｜第 4 章笔记

这一章的工具，我先按动作记：读外部信息的是感知，改变外部状态的是执行，把任务交给人或其他 Agent 的是协作。MCP 让这些工具用相近的方式列出名称、参数和返回值；名字清楚不够，我还得看调用后的结果说了什么。

## 4-1：工具不是越多越好

离线演示有 126 个工具、8 道题。全量注入用 93,040 token，主动发现用 7,796；一次性预筛只答对 4/8，主动发现是 8/8。这里的模型是脚本化 mock，数字只说明这套演示的路由机制。作者的真实 Qwen3-4B 两组都是 3/3，主动发现更快，却没测出准确率提升。我会把“省上下文”和“答对题”分开记。

## 4-2：先找，再读

本机离线流程先 grep，定位到 5 处，再读文件；知识库搜到 1 个文件。我喜欢先定位、后展开的顺序，材料多时尤其省事。但这次没读私人日历，也没接 Notion。工具列表里有入口，不等于我已经拿到数据。

## 4-3：转换格式会丢东西

样例柱状图上 Q4 是 180M，PDF 抽出的文本层里却没有四个季度的精确数值。只给模型文字，它自然很难回答图上的数字。作者的四问历史对照中，原生多模态和按需工具路线各 4/4，先抽文本是 0/4。这只是四道题；我本机只生成并检查样例，没有重跑视觉模型。

## 4-4：我也要看它如何拒绝

我用 CLI 在限定目录写入一个合法 Python 文件，又试了语法错误和越界路径。后两次都被拒绝。执行工具若能说明“哪里没通过”，比一声含糊的失败有用。本机只碰了文件写入；作者历史记录里，日历和邮件仍缺凭据。

## 4-5：等待也是一种状态

人工审批可以批准、拒绝，也会超时；超时后迟来的回复不能重新启动旧操作。Windows 上的测试原来卡在匿名管道读取，我把等待方式改成可超时轮询，17 项测试通过。这次没有给任何人发通知；作者记录里的真实邮件、IM 和 Slack 通道也仍未配置。

以后我看一条工具调用，先问它是观察、修改，还是等待别人；接着核对权限、范围和返回值。能调用，不等于该调用，更不等于已经做成。
