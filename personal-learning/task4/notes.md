# Task 4｜第 4 章笔记

4-4 我试着写一个 Python 文件，正常代码写进去了，语法错的没过，想写到工作区外的路径也没过。做完这几步，我觉得工具先按“会不会改动东西”分，比按名字背一遍好记。读文件、搜索是感知；写文件、运行命令是执行；请人批准或让子 Agent 接手是协作。MCP 让它们用统一的接口列出来，但是否真的做成，还得看返回值。

## 4-1：126 个工具怎么放

离线演示的八道题里，全量注入用 93,040 token，主动发现用 7,796；一次性预筛只答对 4/8，主动发现 8/8。这里用的是脚本化 mock，适合看选工具机制，不能拿来证明真实模型准确率提高。作者用 Qwen3-4B 跑的两组都是 3/3，主动发现更快，却没多做对题。

## 4-2：先定位，再打开

本机离线流程先 grep 到 5 处，再读文件，最后在本地知识库搜到 1 个文件。这个顺序挺实用，不必把整份材料先扔给模型。不过我没接私人日历和 Notion；列得出工具，不代表已经读得到里面的资料。

## 4-3：同一个 PDF，交出的信息可能不同

图上 Q4 标着 180M，PDF 文本层抽不出四个季度的精确数字。把图片先转成文字，问题就可能在这一步丢掉关键证据。作者的四问历史对照中，原生多模态和按需工具路线各 4/4，先抽文本是 0/4。我本机只生成和检查了样例，没有重新跑视觉模型。

## 4-4、4-5：拒绝与等待

文件写入那三次，让我看到合法写入、语法拦截和越界拦截分别长什么样。外部日历、邮件的写入没有在本机跑。协作工具还要处理人的回复：待批准、批准、拒绝、超时，都是不同状态。Windows 上原脚本等匿名管道会出问题，我改了等待方式，相关 17 项测试通过；这次没有发送真实通知。

下次碰到新工具，我会先看它要读什么、改什么，谁有权允许它做，以及失败时留下什么信息。
