# 第 10 章｜多 Agent 协作笔记

翻译项目的 dry-run 先让我看了各个角色会读多少内容：Manager 只保留计划和文件索引，正文交给翻译与校对角色。这次预演没有翻译新书，不过上下文如何增长已经能看出来。真正的质量和成本差别，我仍要回到作者的实际双组记录去看。

## 分角色以后，信息怎么过去

角色切换可以沿用完整上下文，也可以只交接任务、文件路径、已完成步骤和剩余问题。前者细节不容易丢，后者读得少、权限也更清楚，但交接包少写一个条件，接手者就可能沿着错误理解继续做。角色名本身不能保证职责切换，Skill 的规则有没有实际加载也要查。

我读提议者与审核者、管理者分工和去中心化方案时，会先找新增的信息来自哪里。审核者如果只重述提议，没有执行结果或独立证据，讨论再多也不见得能找到错误。

## 并行之后，还要会收尾

多个网站同时查，可以缩短独立任务的等待，但找到一条答案就取消其他任务之前，得先核实它是否真的命中。取消消息发出后，也要等 worker 确认结束，关掉浏览器与后台资源。相关本机测试检查了提前终止、完成确认和重复消息，没有在这次发起新的在线并行搜索。

电话加电脑的注册流程还要管两个世界的状态：哪句话说过，哪个字段填过，提交是否发生。历史 WebRTC 和浏览器记录有这条链路，本机做的是编排与验收器回归，没有拨打真实电话或提交外部表单。

## 小镇和狼人杀

小镇社会实验的范围很大，作者记录的是三组各 25 个 Agent、两个虚拟日。我这次没有重跑这些模型调用。观察到互动，也不能直接推断某种社会行为稳定出现，还要看对照和失败传播。

狼人杀我跑了确定性离线局，信息隔离通过，游戏按规则结束；报告同时注明没有真实 LLM 策略和语音回环，只完成了两个完整循环。这个结果适合检查法官状态与权限，不能写成语音狼人杀正式验收完成。

文件协作、消息格式、重试、取消和权限这些事看上去很琐碎，但一多角色就都变成实际问题。我把六项的本机操作与历史活动放在[逐项进度](progress.md)里。
