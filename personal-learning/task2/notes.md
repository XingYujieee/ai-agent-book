# 第 2 章初学者笔记：上下文工程

我把“上下文”理解为模型这一轮实际收到的全部信息：系统规则、用户任务、工具定义、之前的消息和工具返回。文字相同但排列、来源或出现时机不同，模型可能做出不同决定。

## 1. 本地模型与工具调用（2-1）

Ollama 是本机运行模型的服务，Agent 程序是客户端。模型提出 `tool_call`，客户端执行工具，再把观察送回模型；模型不会因为“会说出工具名”就自动执行工具。

本机 `qwen3:0.6b` 的流式输出显示了思考、工具调用和最终回答。第一次任务虽并行调用了两个工具，却把天气工具误选成 `code_interpreter`；明确工具名后调用正确，但把天气观测时间当成当前时间。第三次强调字段来源后取对了时间字段，却把 UTC 偏移的符号写错。这让我知道**工具调用成功与最终回答正确是两项检查**。

性能基准的五次单流平均解码速度约 317 tok/s，平均首 token 时间约 2.115 秒。前缀命中和未命中的平均首 token 时间分别约 2.131 秒和 2.159 秒，差异很小，不能从这台电脑的一组数字推出普遍加速倍数。并发从 1 增到 8 时，聚合吞吐上升，单请求平均速度下降。

## 2. 注意力与 KV Cache（2-2、2-3、2-8）

注意力矩阵的行可看成当前查询 token，列是它能看的前文 token。重新画出的三层图右上角全黑，原始矩阵未来位置的最大注意力权重是 0，显示因果遮罩。后两层第一列更亮，说明这个例子里首 token 得到了较多注意力；不能把单张图解释成模型总是只看开头。

KV Cache 复用的是**相同前缀**的中间计算结果。工具定义乱序会改变前缀；历史结果里，乱序工具的缓存 token 占输入 token 比例为 3.4%，正确顺序为 10.1%。滑动窗口组虽然有 67.9% 的缓存占比，却没完成任务，说明缓存比例高不能代替任务正确性。它输入短，分母也更小。

2.8 的历史矩阵显示，加入末尾状态栏后，模型回答 token 对状态栏区域有可测注意力；对应的三次回答中，有状态栏组拒绝越过 3 次电话上限 3/3，无状态栏组 2/3。样本太少，不能据此断定状态栏总能防止越权。

## 3. 提示工程与提示注入（2-4、2-5）

提示工程实验应固定任务集合，只改变语气、规则组织或工具描述。仓库历史 Tau-Bench 的基线为 7/10，去工具描述组为 9/10；这个方向没有复现“描述越完整一定越好”的直觉。每组只有十题，应先记录事实，再查不同任务的具体失败点。

提示注入来自不可信内容试图越权控制 Agent。2.5 分直接输入、网页内容和记忆污染三类；防御从无防御到加提示、标来源、运行时拦截。我这次百炼模型在 12 个条件下各跑 3 次，攻击成功数全部为 0。基线也是 0，所以**本次没有可计算的防御增益**。程序末尾的固定“成功率显著下降”文案与这次矩阵不符，应以数据为准。

## 4. Skill 的按需加载（2-6、2-7）

一个 Skill 可以先只暴露名称和用途；任务命中后再读完整规则；需要操作细节时才读参考文档或脚本。本机离线演示按这三层加载，并生成 9 页 PPT；它证明流程可执行，不能证明模型自己选择了 Skill。仓库作者的 13 页论文 PPT 和四张来自原 PDF 的图经过我重新验算，属于历史运行证据。

我按聊天里明确表达的偏好，为学习心得写了 2.7 Skill 初版。它有触发条件、四条带示例的原则、作用范围和例外。由于没有本人原创文章，暂时无法验证它能否复现个人文风。

## 5. 状态栏与压缩（2-9、2-10）

状态栏把当前时间、工具调用次数、TODO 和错误提示放到临近下一次生成的位置。本机简单读文件对照中，两组都正确调用一次工具并回答，说明“加了状态栏”不等于每个任务都会更好。仓库历史 65 次运行也呈现混合结果：时间戳条件有帮助，TODO 和详细错误条件在那批任务里并未提高通过数。

压缩应减少占用，同时保留任务所需事实和来源。2.10 的六策略对照要同时看：任务是否完成、token、压缩前后长度、溢出次数和引用保留。六组在四轮内都没有最终答案；无压缩和逐条摘要各有一次预算溢出，其余四组没有。六组保存的文本总量都比原文长，比例为 107.6%—171.8%。这说明本次“摘要”没有节省这项长度指标，也不能从无溢出直接推断任务成功。各组工具次数不同，token 差异不能直接归因于压缩算法。本次还使用模拟搜索，不能把生成的创始人现状当作实时事实。

## 我的检查顺序

1. 先看这是本机新运行，还是仓库作者历史数据的复算。
2. 核对模型、后端、任务、预算和工具是否一致。
3. 从轨迹找实际完成的工具调用与返回值。
4. 再检查最终答案是否准确使用返回值。
5. 最后比较成功率、token、延迟与异常；少量运行只描述观察，不推广为规律。
