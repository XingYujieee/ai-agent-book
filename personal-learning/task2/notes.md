# Task 2｜第 2 章笔记

第 2 章的实验不少，我先抓住一个问题：每次轮到模型回答，它手里到底多了什么，又少了什么？

## 本地模型与工具（2-1）

Ollama 在本机跑模型，Agent 程序接住 `tool_call`、执行工具，再把结果交回去。模型写出一个工具名，并不等于工具已经执行。

我试的 `qwen3:0.6b` 能并行调用，却也会把天气工具选成 `code_interpreter`。工具选对以后，它拿天气观测时间冒充当前时间；等我明确指定字段，又把 UTC 偏移写反。三次运行里，错误都发生在不同位置，所以只报一个“成功调用工具”实在不够。

本机基准五次单流平均约 317 tok/s，首 token 约 2.115 秒。缓存命中和未命中的首 token 时间约 2.131、2.159 秒；并发从 1 加到 8，聚合吞吐上去，单请求速度下来。这些数字只代表我这台机器和这组设置。

## 注意力、缓存、状态栏（2-2、2-3、2-8、2-9）

我重画的注意力图，右上角是黑的：模型在当前位置不能看未来 token。后两层第一列较亮，说明这段短提示里第一个 token 得到更多注意力，不能推成普遍规律。

KV Cache 复用相同前缀。仓库历史结果里，工具定义顺序稳定时缓存占比 10.1%，乱序时 3.4%；滑动窗口那组达到 67.9%，题却没做完。数字高，可能只是输入更短，不能代替任务结果。

状态栏把当前时间、调用次数和待办放到眼前。本机简单读文件题，加不加都答对；仓库那组电话上限的小样本，有状态栏 3/3 拒绝越限，无状态栏 2/3。它值得继续试，但三次回答还不够写成定律。

## 提示词和提示注入（2-4、2-5）

仓库 Tau-Bench 十题里，基线 7/10，移除工具描述那组 9/10。这个结果和“说明越详细越好”的直觉相反，我会先看每道错题的具体原因。

提示注入我在百炼模型上跑了十二个条件，每个三次，攻击成功数都是 0，连无防御组也一样。程序最后仍打印“防御显著有效”，这句不能照抄。基线没有被打中，就没法从这次运行算出防御带来了多少收益。

## Skill、写作与压缩（2-6、2-7、2-10）

Skill 可以先只给模型看名称和用途，相关时再读完整规则，必要时才翻参考材料。本机离线流程生成了 9 页 PPT；这是流程演示，不是模型自主选 Skill 的证据。作者的 13 页论文 PPT 和原 PDF 图片，我做的是历史材料复核。

写作 Skill 用了我口述的几个风格词，四篇样文都是生成的。它们适合用来挑选表达方式，不能当成我的原创范文。这个区别在现在回看笔记时尤其明显。

六种压缩策略在四轮内都没交出最终答案，保存的文本还比原文长，为 107.6%—171.8%。无压缩和逐条摘要各发生一次溢出，另外四组没有。少一次溢出不等于答完题；这组还用了模拟搜索，不能拿生成内容当实时资料。

这章我最常用的检查办法，是把模型的输入、工具返回和最后一句回答排在一起看。哪里接不上，问题通常就从哪里开始。
