# Task 2 学习心得

这一章让我开始把上下文当作一份会不断变化的工作记录，而不是一整段提示词。工具定义告诉模型能做什么，工具返回告诉它刚才发生了什么；状态栏把分散在历史中的信息提炼出来，压缩则要决定哪些信息不能丢。

我在本机运行了 0.6B 小模型，看到它可以同时请求两个工具，解码也很快。但我也看到它会选错工具，或者把天气数据的观测时间误认成当前时间。即使我明确告诉它使用哪个字段，它仍把 UTC 偏移符号写反。这让我不再把“模型调用了工具”直接等同于“回答可信”。

重新画注意力热力图时，我第一次把因果遮罩与注意力落点对应起来：未来位置没有权重，后层对第一个 token 的权重在这条短提示里明显更高。看 KV Cache 结果时，滑动窗口组缓存占比很高却没有完成任务，提醒我效率指标必须和任务结果一起看。

提示工程和提示注入的结果也让我练习克制。历史 Tau-Bench 中，移除工具描述的十题成绩反而高于基线；我自己的提示注入 36 次运行中，连无防御组都没有攻击成功。这两组数据都不支持简单的“加一层规则就一定更好”。我会先保留任务、次数和原始矩阵，再写结论。

PPT Skill 的离线流程让我理解了按需加载的三层结构，但内置大纲不等于 Agent 真的自己选了 Skill。我做的写作 Skill 初版也只体现了已经明确说出的偏好；没有本人原创文章和修改意见，我不会把它写成个人风格复现成功。

六种压缩策略跑完后，我发现“调用了摘要模型”也不等于“上下文真的变短”：六组累计文本都变长了，四轮内也都没有交出最终答案。模拟搜索还让我没法验证研究内容的真实性。第 2 章最有用的习惯，是在每一步都问：模型实际看到了什么，工具实际做了什么，最后的判断有哪条证据支持。
