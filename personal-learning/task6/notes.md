# 第 6 章｜交互与异步笔记

定时器演示只跑了两秒，到点以后产生事件，再唤醒处理流程，模型动作是 mock。邮件入口则还缺真实服务凭据。把它们放在一起看，我才分清“事件调度能工作”和“能收到我的真实邮件”是两层事情。

## 等待的时候还能做什么

异步演示里有真实子进程的进度，也能中途取消、保存检查点。重启运行时以后，正在运行的任务恢复成 suspended，留下最后已知进度，并不会假装原进程还活着。Windows 上有个取消测试用了 POSIX 的进程探测方式，这次改为核对已经等待结束的子进程返回码，取消和进度冻结的检查还保留着。

6-3 又往前走了一步：运行时能并行等工具，并不代表模型协议本身支持工具未完成时继续接收用户引导。我读作者的原生异步对照时，会同时找工具状态和用户更新何时进入模型，避免把两个层次混起来。

## 语音为什么容易显得迟钝

传统语音链路要依次经过 VAD、ASR、模型和 TTS，前面等一句话结束，后面才开始处理，延迟会逐段累加。流式和端到端方案想缩短等待，但前缀越短，信息也越不完整，停顿和噪声就可能被误判。

仓库的 Qwen2-Audio 记录没有复现预期的 100–200ms 前缀延迟，实测约 8.4–11.3 秒。我这次没有下载它的全部大模型权重，不能在本机重新核验那部分文件。音频质量同样不能从转写文字推断；可控 TTS 要听实际音频，端到端方案还要检查语义和副语言有没有一起保留下来。

## 屏幕与机器人

Computer Use 每点一次，页面就可能变一次，所以旧截图上的坐标需要重新核对。作者留下了原生 Computer Use 和开放模型浏览器路线的实际记录，我这次做的是本地配置与证据相关检查，没有拿它们冒充新的一次桌面任务。

机器人部分我在 RTX 3070 Laptop GPU 上跑了三个自包含实验。模拟控制上限的 2,304 个 episode 全部成功；闭环比较跑了 3,456 个 episode；RGB 域变化用了三组种子、四种训练条件，共 49,152 条训练样本，三个校验器都通过。RGB 的干净训练组在原域约 92.7%，目标域却只有约 56.3%；完整随机化的目标域约 75.5%，原域则降到约 88.1%。这次我能具体看到适应新环境的收益和代价，而不只是记住“随机化有帮助”。真机还需要设备、校准、急停和现场观察，本机模拟没有替代这些条件。
