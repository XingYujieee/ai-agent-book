# 第 5 章｜代码生成笔记

我先跑了骑士与无赖的离线求解器，十二题全部答对。这个结果容易让人觉得“用代码就是更准”，但对照一下作者的真实模型实验就没那么简单了：模型还得把题意写成正确的约束，求解器只能保证自己收到的约束被认真执行。那组代码辅助的成绩反而低于纯推理。我把“程序算得对”和“题目翻译得对”分开记了。

## 一次修改怎么才算做完

Coding Agent 的基本动作是读文件、搜索、写补丁、运行和检查。对我来说，关键是这些动作能接起来：修改以后用测试核对，失败时回头定位，而不是写完文件就结束。跨厂商接管也有类似要求，交接过去的工具结果、任务状态和消息格式都得能用。作者的中立轨迹格式接管六组都成功，原样传递和简单删掉推理内容却会遇到厂商拒绝；流被截断时，接出来的 JSON 即便合法，里面的城市名也可能已经错了。

数学题、逻辑题和业务规则都可以交给代码处理，不过我不会只看用了哪个库。AIME 的代码组是 16/30、纯推理 11/30，配对检验 p=0.125；规则代码化那组也没有胜过控制组。这些是作者以前留下的结果，我这次做了文件核对和相关本地检查，没有重跑那些在线模型。

## 能看见的产物

动态表单这次真的生成了 HTML。我检查了往返日期和舱位信息的级联，也看了模拟提交后汇总的 JSON；它还没有替我订票。视频剪辑的冒烟流程用了生成素材，输出了一段约 5 秒的 H.264/AAC 视频，同时留下 Blender 脚本，实际渲染走的是 ffmpeg。Windows 上找不到默认字体的问题也在这一步暴露出来，补上字体路径后才跑通。

论文转 PPT、讲解视频和 CAD 对照，我主要查的是仓库里的历史材料。代码适合表达页码、布局、尺寸这些明确约束，但最终仍要检查图片、音频或网格；只看脚本没有报错，还看不出漏字、错图和孔径偏差。

## 从新格式到新程序

日志解析的离线演示先遇到新格式，再安装预置解析函数，测试后热加载，最后复用到三条混合日志。我能在本机核对这条流程，但函数不是模型现场写出来的。日志诊断、ERP、界面定制和 Agent 自举则更依赖真实环境。我这次把本地回归与作者历史运行分开放，尤其保留了 5-16 对照文件没有随当前 Git 快照提供这件事。

5-15 的权限对象需要 PostgreSQL，这台环境没有配置相应测试库，我没去连接别的数据库。读这部分代码时，我关心的是调用者能不能绕过受控接口：权限和数据校验如果只写在提示词里，动态生成的业务代码漏一条判断就会出问题。
